# 03 数据库设计

- 类型：MySQL 8（`utf8mb4`；个别 AI 表用 `utf8mb4_0900_ai_ci`，注意字符集差异）。
- DDL：仓库根目录 `./init.sql`（含全部表结构 + 一套种子数据）。
- 连接：`backend/src/config/database.js`（mysql2 连接池，上限 10），读 `.env` 的 `DB_*`。

## 2. 核心表结构说明

### `pages`（页面）⭐
| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | int PK | |
| title / slug | varchar | slug 唯一，`home` 为特殊首页 |
| content | longtext | **历史纯 HTML 内容**（迁移兼容） |
| excerpt / featured_image / meta_title / meta_description | — | 摘要与 SEO |
| published | tinyint(1) | 是否发布，前台只读 `published=true` |
| sort_order | int | 排序 |
| created_by | int FK→users | 作者，删用户置 NULL |
| template_data | json | **PageBuilder 组件 JSON**（含 `components[]`） |

> ⚠️ 双内容并列：当前 PageBuilder 主要读写 `template_data`（JSON）；`content`（HTML）为旧版遗留，种子首页在 `content` 中仍存在原始 HTML，二者可能不同步。

### `settings`（站点设置）
| 列 | 类型 | 说明 |
| --- | --- | --- |
| setting_key | varchar 唯一 | 设置键 |
| setting_value | longtext | 值 |
| setting_type | enum string/text/number/boolean/json | 决定解析方式（json 类型存 JSON 字符串） |
| site_theme | varchar | 冗余的主题字段 |

常用键（依据种子数据）：`site_name`、`site_description`、`site_logo`、`site_favicon`、`site_keywords`、`contact_email/phone`、`address`、`icp_number`、`icp_link`、`site_statement`、`copyright`、`social_links`(json)、`quick_links`(json)、`nav_layout_style`、`site_theme`、`theme_overrides`(json)、`theme_background`、`footer_layout`(json)、`footer_social_links`(json)、`wechat_qrcode`、`analytics_code`。

### `docs`（文档站）
`parent_id` 自引用形成树；`type` ∈ doc/folder；`content_format` ∈ html/markdown；`status` ∈ draft/published；`published_at` 发布时间。slug 唯一。

### `news`（新闻中心）
| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | int PK | |
| title | varchar(255) | 标题 |
| date | date | 发布日期（`YYYY-MM-DD`，可空） |
| summary | text | 摘要 |
| link | varchar(500) | 链接（支持相对 `/pages/…` 与绝对 `https://…`） |
| image | varchar(500) | 图片 URL |
| pinned | tinyint(1) | 是否置顶（`最新` 模式下优先展示） |
| published | tinyint(1) | 是否发布（公开列表只读 `published=1`） |
| created_at / updated_at | timestamp | |

> 日期约定：列存 `YYYY-MM-DD`；后端 `normalize` 仅收该格式（字符串或 Date 均转此格式），否则 `null`；读取统一 `DATE_FORMAT(date,"%Y-%m-%d") AS date` 输出为字符串，避免 mysql2 把 `DATE` 返回成 JS Date 对象。

### `notification_settings`（邮件）
一行 `type='email'`（UNIQUE）。`password_encrypted` 为 varbinary 加密存储；`default_recipients`/`contact_recipients` 为 JSON；`contact_enabled` 决定联系表单是否触发邮件；`test_status`/`last_error` 记录测试结果。

### 认证相关（`users` / `refresh_tokens`）
- `users.role` ∈ admin/editor/viewer；`password` 为 bcrypt 哈希。
- `refresh_tokens.token_hash` 为 refresh token 的 SHA-256；轮换时旧行记 `revoked_at` + `replaced_by_id`。

## 3. 表间关系示意

```
users ──1..n──► refresh_tokens
users ──1..n──► activity_logs
users ──1..n──► user_sessions
users ──1..n──► pages          pages ──1..n──► page_components / component_blocks
pages ──►── tags   (多对多，经由 page_tags)
tags ──1..n──► page_tags ◄──1..1── pages
docs ──► own-parent_id（自引用树）
navigation ──► parent_id（自引用）
```

常见 JOIN：给页面取标签 → `page_tags` ⋈ `tags`（见 `routes/pages.js` 的 `attachTags`）。

## 5. 迁移与兼容注意

- `component_blocks` 与 `page_components` 并存，均带 sort_order / page_id 外键；新增页面应确认写入的是哪一张，避免双写歧义。
- `settings` 表 `site_theme` 列与 `setting_key='site_theme'` 行并存，主题读取以哪个为准需看 `SettingsContext`/`settings.js` 实现（当前 phase 前端 `_app.tsx` 读 `settings.site_theme`）。
- 导入时注意 AI 相关的 UTF-8 排序规则（`utf8mb4_0900_ai_ci`）需 MySQL 8 支持。
