# 07 浏览器缓存与弱网回退

> 单一权威说明。负责「弱网/离线时优先使用浏览器内已缓存内容，而不是空等后端」。涉及前端缓存工具层、后端版本接口、图片 Service Worker、语言缓存与已禁用语言守卫、切页幕布预取五个部分。

## 1. 目标与总体思路

前台每一页的界面信息（导航、站点设置、最新新闻、语言表）默认是**每次访问实时请求后端 API** 获取。为改善弱网体验，做了「条件更新式缓存」：

- **有缓存 → 立即返回缓存渲染**（stale-while-revalidate），不阻塞 UI 出现；
- 同时在**后台**调一个极轻量的**版本接口**比对缓存是否过期：未变则什么都不做（不重复拉全量），已变则重新拉取并刷新缓存；
- 连**版本接口都请求失败**（弱网）→ 仍用旧缓存，并弹出右下角横幅「拉取最新数据失败，请尝试刷新」+ 刷新/关闭按钮；
- 图片/静态素材由 **Service Worker** 以 stale-while-revalidate 缓存，弱网/离线时之前加载过的图片可继续显示。

**边界**：首次访问且无缓存时，仍必须走一次网络（没有可复用的内容）；前台页面正文（SSR `getServerSideProps`）**不做**浏览器缓存，仍每次由服务端拉取。

## 2. 后端：版本接口 `GET /api/content/status`

- 文件 `backend/src/routes/content-status.js`；挂载于 `server.js` 的 `/api/content`。
- **无需鉴权**，按语言返回各缓存数据源最近的 `updated_at`，供前端比对版本：

```http
GET /api/content/status?lang=zh
# → { success:true, data:{ navigation, settings, news, languages } }
```

- `data` 各字段为对应表全局最近的 `updated_at`：
  - `navigation`：`navigation` 表（仅 `is_active=1` 且 lang 匹配）
  - `settings`：`settings` 表（`lang IN ('zh', ?)`，与设置读取口径一致）
  - `news`：`news` 表（仅 `published=1` 且 lang 匹配）
  - `languages`：`languages` 表（不分语言）
- 判定完全依赖各表已有的 `updated_at` 列，**无需改表**。前端把「写缓存那一刻的版本号」与最新版本比对，实现条件更新。

## 3. 前端缓存工具层 `frontend/src/utils/dataCache.ts`

- **持久化**：`localStorage["pailink-ui-cache"]`，结构 `{ [key]: { data, version, cachedAt } }`；键形如 `navigation:zh`、`settings:zh`、`news-latest:zh:3:p`、`languages`。
- **核心 `getCachedData({ key, entity, lang, fetcher })`**（SWR）：
  - **有缓存** → `Promise.resolve(cache.data)` **立即返回**，并触发后台 `backgroundRevalidate`：调 `/content/status` → 版本一致则不动；已变则 `fetcher()` 重拉并写缓存（触发 `cache-changed` 事件）。
  - **无缓存** → 等网络全量拉取（`fetcher()` + 尽力记录基线版本），写缓存后返回。
  - 弱网（版本接口失败）→ `markStale()`，返回旧缓存。
- **弱网状态**：模块级单例 `markStale()/clearStale()/isStale()/onStaleChange()`。
- **缓存变更事件**：`onCacheChanged(key, cb)`，后台刷出新数据后消费点据此自动上屏新内容。
- **数据源注册表**：`registerSource/unregisterSource` + `refreshAllSources()`（全量强制重拉，刷新按钮用）。
- **并发去重**：同 key 并发取数复用同一 Promise。

### 消费点与缓存键

| 界面信息 | 缓存键 | 消费点 | fetch |
| --- | --- | --- | --- |
| 站点设置 | `settings:{locale}` | `contexts/SettingsContext.tsx` | `settingsApi.get(locale)` |
| 导航 | `navigation:{locale}` | `components/Layout.tsx`（供 `ThemeAwareHeader`） | `navigationApi.getAll(locale)` |
| 最新新闻 | `news-latest:{locale}:{count}:{pin}` | `PageBuilder/previews/NewsListPreview.tsx`（公开页才缓存，后台编辑器画布不经缓存） | `newsApi.latest(...)` |
| 语言表 | `languages` | `i18n/LocaleProvider.tsx` | `languagesApi.getAll()`（含 `is_enabled`） |

另有 `frontend/src/hooks/useCachedData.ts` 封装 `getCachedData` + 缓存/弱网订阅，供需要时复用。

## 4. 弱网横幅 `StaleDataBanner`

- 文件 `frontend/src/components/StaleDataBanner.tsx`；挂在 `_app.tsx`，**fixed 右下角**常显。
- 触发：有缓存但后台版本校验/刷新失败（弱网）。
- 文案「拉取最新数据失败，请尝试刷新」；按钮：**刷新**（`refreshAllSources()`，全量重拉成功后隐藏；仍失败保持显示）、**关闭**（仅隐藏，继续用缓存）。用 lucide-react 图标与主题变量配色。

## 5. 图片缓存 Service Worker `frontend/public/sw.js`

- **目的**：弱网/离线时，之前加载过的**同源图片**从浏览器缓存直接显示。
- **策略**：stale-while-revalidate。命中缓存→立即返回；后台再拉最新并更新缓存（替换图片会静默刷新，不长期陈旧）。
- **范围**：仅同源 GET；只处理 `request.destination === 'image'` 或常见图片扩展名（`jpe?g|png|gif|webp|svg|ico|bmp|avif`）。**页面导航（`navigate`）与 `/_next` 构建产物一律不缓存**，避免服务旧代码/旧页面。
- **健壮性**：只缓存 `status === 200` 的完整响应（206 分段/错误响应跳过，Cache API 不支持 206）；离线且无缓存时回退一个兜底 `404`，绝不让 `respondWith(undefined)` 抛错；缓存写失败静默。
- **版本化**：`CACHE_NAME = pailink-static-<VERSION>`；`activate` 时清理旧版本缓存。
- **注册**：`_app.tsx` 在页面 `load` 后懒注册 `/sw.js`（避免与首屏竞争），注册失败静默降级。
- **路由**：`middleware.ts` 的 `EXCLUDED_PREFIXES` 已排除 `/sw.js`，绕过语言路由中间件；生产 nginx `location / → 3001` 由 Next 从 `public/` 提供该文件。
- 与 nginx 的关系：生产 nginx 已对 `jpg|png|webp|svg` 配 `Cache-Control: public, immutable` + `expires 30d`（见 [06](./06-部署与运维指南.md)）——这处理「HTTP 浏览器缓存」，SW 处理「弱网强缓存」，二者互补。

## 6. 语言表缓存 + 已禁用语言路由守卫

- **缓存**：`LocaleProvider` 缓存 `languagesApi.getAll()`（返回**全部**语言的 `is_enabled`），弱网时语言切换器可用缓存工作；版本接口含 `languages`，后台刷新自动同步。
- **切换器显隐**：`ThemeAwareHeader` 用上下文已启用语言子集；挂载（`hydrated`）后同步读缓存判定，**出现时机与导航项对齐**。仅当已启用语言数 `> 1` 才显示；缓存只有一种语言时**全程不显示**（无空态闪现）。
- **守卫（拦截已禁用语言路由）**：`LocaleProvider` 校验 URL 首段——若为**已知语言后缀但已被禁用**，`router.replace` 到去掉该前缀的中文路径（`/en/foo → /foo`），防止有人经旧缓存/旧链接停留在已禁用语言的界面。**仅依据已确认的语言表触发**；离线无法确认时不动，交给弱网横幅。
- 移除重复：`ThemeAwareHeader` 不再自行 `getEnabled()`，统一使用 `LocaleProvider` 缓存源。

## 7. 切页幕布预取（转场加速）

- 页面转场 `components/Cover.tsx`：点击链接 → 幕布上划盖满（即时）→ `router.push` → 等目标页 `routeChangeComplete`（SSR 取数）→ 上移露出新页。弱网时 SSR 慢会导致幕布久盖。
- 加速：新增**链接预取** `router.prefetch`——`pointerover` 悬停站内链接时后台预取目标页数据（`toHref()` 归一化链接、每个 href 预取一次、跳过当前页）。点击时命中已预取数据 → `routeChangeComplete` 快速到达 → 幕布即时上移切页，不“等最新数据当场拉”。
