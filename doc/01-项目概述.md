# 01 项目概述

## 1. 产品定位

一套**可二次开发的企业官网建站系统（CMS）**。核心价值：

- **后台无代码建站**：通过可视化拖拽 PageBuilder 组合 30+ 页面组件，实时预览并配置主题/字体/站点资料。
- **前台即渲染**：访问者看到的是按 slug 渲染、已发布的页面组合。
- **可扩展**：内置文档站（Docs）、站内通知/联系表单、访问统计、AI 写作辅助等能力。

> 归属：当前部署站点为**深圳市电湃科技有限公司**（见 `.env` 的 `SITE_NAME`、`FROM_EMAIL=@powerbelltech.com`）。代码由原始模板（元兴信息官网）演进而来，种子数据仍有旧模板残留，见 [02](./02-技术架构与代码结构.md#已知技术债与注意点)。

## 2. 核心能力

| 能力 | 说明 | 落地位置 |
| --- | --- | --- |
| 可视化页面构建 | 拖拽组件、配置属性、页面发布/上线、模板套用 | `frontend/src/components/PageBuilder/` |
| 主题系统 | 语义化色板、多主题、参数化强度调节、字体管理 | `frontend/src/styles/themes.ts` |
| 后台管理 | 仪表盘、页面、导航、素材、标签、模板、通知、设置、AI、分析 | `frontend/src/pages/admin/*` |
| 文档站 | 树形文档、富文本/CKEditor 编辑、侧边栏 | `frontend/src/pages/docs` + `backend/src/routes/docs.js` |
| 联系表单与通知 | 前台提交 → 入库 → 站内/邮件通知 | `routes/contact.js`、`contact_submissions`、`notification_settings` |
| 访问统计与分析 | 访问埋点、日志、图表 | `stats.js`、`visit_stats`、`activity_logs` |
| AI 辅助 | 供应商配置、提示词模板、内容生成 | `ai.js`、`ai_provider_settings`、`ai_prompt_templates` |
| 素材管理 | 图片/文件上传、文件夹、系统内置素材 | `system-default/`、`upload.js` |

## 3. 技术栈总览

| 层 | 技术 | 要点 |
| --- | --- | --- |
| 后端 | Node.js + Express 4 + MySQL（mysql2 连接池） | 主入口 `backend/src/server.js`，端口 3003 |
| 认证 | JWT + Refresh Token（HttpOnly Cookie 轮换） + bcrypt | `backend/src/middleware/auth.js` |
| 参数校验 | Joi | `backend/src/middleware/validation.js` |
| 上传 | multer + sharp（图片处理） | `backend/src/routes/upload.js` |
| 邮件 | nodemailer | `backend/src/utils/mailService.js` |
| 安全 | helmet、cors、express-rate-limit、compression | `server.js` |
| 前端 | Next.js 14（Pages Router）+ React 18 + TypeScript + Tailwind | 端口 3001 |
| 前端动画/可视化 | framer-motion、react-dnd（拖拽）、chart.js、react-chartjs-2 | PageBuilder / 分析页 |
| 富文本 | CKEditor（UMD 版，`frontend/public/ck-umd`）+ isomorphic-dompurify（XSS 清洗） | 文档/内容编辑 |
| 文字/样式工具 | marked（Markdown）、clsx、lucide-react、@tabler/icons-react、bootstrap-icons、@fortawesome/free-brands-svg-icons | 图标/内容 |
| 数据 | `init.sql`（18 张表） | 建库脚本见 [03](./03-数据库设计.md) |
| 部署 | 端口规划 + nginx 反代（普通版 / 宝塔版两套配置） | 见 [06](./06-部署与运维指南.md) |

> 依赖说明：`frontend/package.json` 与 `backend/package.json` 中均含冗余依赖 `"all": "^0.0.0"`（空包），属历史遗留，见 [02-已知技术债](./02-技术架构与代码结构.md#已知技术债与注意点)。

## 4. 主干架构图

```
                                   ┌──────────────────────────────────────────────┐
                                   │                     nginx                    │
                                   │  / → 3001  │  /api、/uploads → 3003  │ 前台443 后台23080 │
                                   └───────┬───────────────┬───────────────────────┘
      访问者                           │               │
  ┌──────────────┐          ┌───────────────┴──┐   ┌───────┴─────────────┐
  │  浏览器       │─────────▶│  Frontend (Next)│   │ Backend (Express)  │
  └──────────────┘          │  3001  Next.js  │   │ 3003  REST API      │
                            └──────────────────┘   └───────┬─────────────┘
                                                          │ mysql2 连接池
                            ┌─────────────────┐   ┌───────┴─────────────┐
                            │ 静态资源          │   │       MySQL         │
                            │  /uploads        │   │  库名 pailink        │
                            │  /system-default │   └─────────────────────┘
                            └─────────────────┘
```

- 后台 `/admin` 在**前台 nginx** 中 `deny all`，只能通过**独立端口 23080** 的后台 nginx 服务块访问（同一 Next.js 实例）。
- 后端通过 `/uploads`、`/system-default` 提供静态文件；前端 CKEditor UMD 资源走 `/ck-umd`。

## 6. 角色与权限分级

角色来自 `users.role`，由 `middleware/auth.js` 的 `requireRole` 控制：

- `admin`：全部管理接口。
- `editor`：页面/素材/统计等编辑类接口（`requireEditor` = admin + editor）。
- 匿名：前台读取、联系表单提交、登录、健康检查等公开接口。

（详见 [04](./04-后端接口文档.md#鉴权约定)）
