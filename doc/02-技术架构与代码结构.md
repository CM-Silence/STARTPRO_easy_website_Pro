### 关键文件职责

- **`src/server.js`**：挂载 helmet（CSP 允许 inline style / data: 图片）、cors、compression、morgan 日志、**智能限流**（根据 JWT 角色分级，见下）、`express.json({limit:'500mb'})`、静态托管 `/uploads`、`/system-default`；启动时调用 `normalizeSystemDefaultSvgs()`。
- **`src/config/database.js`**：对齐 `.env` 中 `DB_*` 变量建连接池。
- **`src/middleware/auth.js`**：`authenticateToken`（Bearer JWT → 校验并装配 `req.user`）、`requireRole(['admin'])`、`requireAdmin`、`requireEditor`(admin/editor)、`logActivity`（在 `res.json` 外层写 `activity_logs`）、`generateToken`/`verifyToken`。
- **`src/middleware/validation.js`**：`validate(schema, property)` 工厂 + 各实体 Joi schema（user/page/settings/notification/query/doc），导出确定性校验器供路由复用。

### 智能限流分级（`server.js`）

| 请求类型 | 限额（/分钟/IP） | 判定方式 |
| --- | --- | --- |
| 无 Token | 1000 | 通用 |
| 普通已登录用户 | 1000 | JWT 解出非 admin |
| admin Token | 10000 | JWT 解出 role=admin |

### `pages/index.tsx` 入口逻辑

匿名访问 `/` 时：

1. 调用 `pagesApi.getBySlug('home')` 查询 slug 为 home 的页面。
2. 命中且 `published=true` → `router.replace('/pages/home')` 渲染前台页。
3. 否则停留在 `/` 展示加载/回退态。

## 3. 关键流程

### 3.1 请求认证 / Refresh Token 轮换（`routes/auth.js`）

- 登录 `POST /api/auth/login`：bcrypt 校验 → 发 `accessToken`（`JWT_SECRET`）→ 生成 refresh token（`crypto.randomBytes(64)`），只存 **SHA-256 哈希** 到 `refresh_tokens` 表，写入 **HttpOnly Cookie**（`secure=production`、`sameSite=lax`、path `/api/auth`），并写 `activity_logs`。
- `POST /api/auth/refresh`：读 Cookie → 查哈希 → 校验未吊销/未过期 → **轮换**（旧 token 置 `revoked_at` 并记 `replaced_by_id`）→ 重新下发。
- `POST /api/auth/logout`：吊销当前 refresh token 并清 Cookie。
- 中间件 `authenticateToken` 校验 Bearer access token；基于 `role` 由 `requireRole` 放行。

### 3.2 PageBuilder 组件渲染流程

1. 后台：拖拽组件（`react-dnd`）→ 属性编辑（各 `editors/*` 编辑器）→ 存为 `pages.data`（JSON，含 `components[]`）。
2. 后端 `pages.js` 存 `data` 字段；历史的纯 HTML 存 `content` 字段（迁移兼容，见 [03](./03-数据库设计.md)）。
3. 前台 `pages/[slug].tsx`：读 `data` → 按 `type` 查渲染器 → 输出带主题 token 的 HTML/JSX。

### 3.3 静态资源与端口规划

| 资源 | 实际来源 | 浏览器路径 |
| --- | --- | --- |
| 用户上传 | `backend/uploads/`（Express 静态） | `/uploads/...` |
| 系统内置素材 | `backend/system-default/` | `/uploads/system-default/...`、`/system-default/...` |
| CKEditor UMD | `frontend/public/ck-umd/`（Next 静态） | `/ck-umd/...` |
| Next 应用 | `frontend`（3001） | 前台 443 / 后台 23080（nginx） |
| 后端 API | `backend`（3003） | `/api`、`/uploads` 经 nginx 反代 |

## 4. 已知技术债与注意点

> 以下为事实性记录，均基于代码排查发现，非指责；接手时请留意。

- **已清理旧模板 seed**：`init.sql` 现为纯建表结构，已移除「元兴信息」旧模板的 seed（site_name/备案号/logo/admin 账号等）；同时移除 mysqldump 临时视图工件。当前 `init.sql` 含幂等多语言迁移块，旧库运行一次即可对齐（见 [03](./03-数据库设计.md#6-多语言增量迁移一次性对齐旧配置)）。
- **冗余依赖**：前后端 `package.json` 均含空包 `"all": "^0.0.0"`。
- **调试日志残留**：`routes/auth.js` 的 `/login` 内有 `console.log('调试登录:...')`、明文密码打印等调试代码，生产建议移除。
- **备份/残留文件**：`frontend/src/pages/admin/pages/index.tsx_bak` 为历史备份文件，混淆目录结构。
- **限流宽松**：admin 每 IP /分钟上限 10000，且 `express.json` body 上限放大到 500mb，正式环境按需收紧。
- **`.env` 明文密钥**：`.env` 含真实 `DB_PASSWORD` 与 `JWT_SECRET`，且**未被加入 `.gitignore` 之外的提交保护**（`.gitignore` 虽含 `.env`，但请勿在不同环境间共享该文件）。
